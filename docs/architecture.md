# Architecture

KaviSeerr is a long-running Node 22 Next.js App Router service. All route handlers run in the Node runtime, dynamically, with uncached private responses. The root page renders a French React interface with a server layout, locally bundled Geist font, Tailwind CSS and Radix dialogs/tabs. `src/lib/client/api.ts` is the browser adapter over the shared contract; server integrations never enter the client bundle. Authentication gates the views, signed HttpOnly cookies authenticate SSE, and logout/expiry resets interface state.

## Data and execution

- `src/types/shared.ts` is the browser-safe contract. `src/lib/validation.ts` validates untrusted request payloads; UI imports only shared types.
- SQLite WAL and FTS5 are initialized lazily in `db.ts`, with schema version 2. A transactional, idempotent migration adds tracked reading status (default `READING`), numeric read/released values, reading timestamps and a progress-provenance marker. It preserves v1 data and never downgrades a newer user_version. Alongside `settings`, `tracked_media`, `catalog_fts`, `catalog_keys`, `download_batches` and `worker_lock`, `imported_chapters`, `observed_chapters`, `source_health`, `update_entries`, `update_chapters` and `worker_state` persist the library, source observations and update scheduling. Stable FTS row IDs avoid scanning the entire catalog on every upsert. No sample catalog or media data is seeded.
- AES-256-GCM encrypts API credentials in SQLite using a generated 0600 settings key, separate from the database. Filesystem/volume access controls remain the operator's responsibility. The app's 0600 access token is independent of that key. Signed browser cookies expire after seven days; rotating the token invalidates them. Login has a process-wide 20 attempts/minute limit without trusting forwarded IPs.
- `instrumentation.ts` starts the durable worker in the Node server. Authenticated routes also ensure it starts. A SQLite lease prevents normal Next module instances/processes from duplicating work. Leases renew every 30 seconds and expire after five minutes; restart recovery may wait for that expiry. Deploy one application replica per SQLite volume.
- Batches persist before enqueue. The worker sets CBZ mode, enqueues, verifies `chapter.isDownloaded` for **all** selected IDs, imports archives atomically, records every imported ID and its numeric chapter/source/series identity in SQLite after atomic import, writes metadata, then scans Kavita. Queue emptiness alone never means completion. Errors remain persisted with safe codes; retry skips already imported archives. A crash during an atomic import may safely rewrite that one chapter on restart.
- Tracking checks all MANGA entries with selected sources at `updateIntervalMinutes` (5–1440, default 15). It chooses one variant per normalized chapter number in selection priority order. Observations, detection groups and automatic batch creation share a SQLite transaction; manual titles produce pending groups. Repeated checks do not duplicate observations, and unfinished check requests survive restart. Three titles can be checked concurrently with a shared two-minute source deadline. Reading progress then has a separate 15-second bound. Existing batches are processed before checks.
- Update groups are persisted by series/source/detection cycle (groups remain whole; maximum 500 chapters per batch). Each chapter links to an automatic or subsequent manual batch. The feed derives queued/downloading/downloaded/error from durable batches; a completed subset of a manual group does not mark its remaining chapters complete. The latest 200 groups and scheduling state are returned to the UI. `checking` is meaningful only while the SQLite worker lease remains live.
- Library ownership counts distinct imported numeric chapter numbers. Progress and unread counts are derived from imports plus persisted Kavita reading progress; source release maxima and metadata chapter counts determine released. Unnumbered specials remain downloadable but do not advance numeric counters. Imports preceding tracking are linked when the series is added. Migration does not infer chapter numbers from pre-v2 batch ID lists or scan arbitrary existing media files; ownership is recorded on successful imports from v2 onward.
- Multi-source chapter tables retain all variants for manual fallback. Automatic substitution after a source download failure is not implemented; the user can select the alternate source explicitly. Anime downloads go through Arr, not Suwayomi. Downloader pause/resume/clear forwards supported Suwayomi mutations, while durable import batches retain their own state.

## Protocol choices

Suwayomi is pinned to release `v2.4.2366` (`40bc5da`). Source IDs use its `LongString` scalar and remain strings end to end. Chapter numbers use `chapterNumber`; extension mutations use `UpdateExtensionInput.patch`. APK/JAR upload is not necessary for repository installs: these use `updateExtension`, the supported path requested in the brief. The app never selects or installs third-party extension stores automatically.

Search fans out with `Promise.allSettled`: AniList, MangaDex, MangaUpdates and local FTS. Each public request has a 2500 ms deadline. No-type searches also query AniList anime independently. Exact normalized aliases merge within one media type; conflicting known provider IDs prevent merging sequels/remakes. This heuristic can miss unrelated-language titles without a common alias. It never promises a universal identity graph. Provider failures remain explicit in the response; partial results are usable. A bounded 30-second in-memory cache reduces repeated upstream queries. Search is query-driven, not an invented discovery feed.

Deep search resolves enabled installed sources in preferred languages, starts a four-second request per source in parallel, streams each result immediately and indexes actual hits. Popular sync iterates a bounded number of pages (1–50) per source and streams progress. These operations progressively index the catalog. Extensions that are unreachable or protected by unsupported challenges can fail independently. Source preferences are stored separately from legacy favorites, which migrate once on first preference access. Empty enabled IDs means all matching sources in Suwayomi order; explicit IDs determine search priority. Every source search/browse persists latency and a safe error code; successful calls above four seconds are slow. Recognizable Cloudflare messages/mitigation headers are classified without exposing upstream bodies. Browsing uses the pinned filter union (all eight types), aliased defaults to avoid GraphQL field conflicts, bounded nested groups and the same FTS indexing as search.

Kavita scans need a configured library including the shared path. Reading progress uses the documented `Search/search`, `Series/{seriesId}` and `Series/volumes` APIs for the configured user's identity. Resolution prefers the exact written folder under `kavitaLibraryPath`; a single exact title/alias match is the fallback, while ambiguous matches remain unresolved. Resolved series IDs persist, so subsequent refreshes skip search. `pagesRead >= pages` marks a numeric chapter complete; partial reads affect the latest reading timestamp but not the highest completed chapter. Current `maxNumber` and legacy `number` fields are supported, and specials do not advance numeric progress. The worker refreshes progress on each check and GET tracked supports a bounded on-demand refresh, up to four entries at once; failures retain prior values. Newer servers use `x-api-key`; legacy mode exchanges the key at Plugin/authenticate and passes a JWT. Metadata is embedded in each CBZ because a loose XML file alone is not sufficient for Kavita. Archives are never extracted into arbitrary paths. Compressed transfers are capped at 256 MiB and declared expansion at 512 MiB. Import uses memory for ZIP rewriting, so provide adequate RAM; oversized chapters fail explicitly. Cover downloads accept HTTPS provider hosts only, cap bytes/time, and refuse redirects. The cover is written as `cover.jpg` as requested; actual cover encoding depends on its provider.

Arr results retain rejection information. Sonarr grabs use `/api/v3/release`; Prowlarr grabs use `/api/v1/search`, so results are not incorrectly sent to Sonarr with foreign GUIDs. Grabs use the upstream search cache and can require searching again after expiry. Existing Sonarr series/indexers/download clients must already be configured externally. Light-novel metadata/tracking is supported; no EPUB text scraping or conversion is implemented.

## Verification and limits

`npm run check` covers ESLint, strict TypeScript, backend and SSE framing tests, including a v1 database migration, source preference migration, filter/browse mappings, update grouping/state transitions, downloader controls and API-key/JWT Kavita progress fixtures, plus a real Next production build. Tests use local protocol fixtures, deliberate failures and synthetic archives. Docker checks use an isolated stack and real pinned Suwayomi, with unconfigured external services and no extension installation. They validate service startup, native SQLite, authentication, API routing, GraphQL settings/extensions/download status, streams and metadata response shape.

Successful local fixture tests do not prove compatibility with every extension, private Sonarr/Prowlarr setup or Kavita instance. Real private-service scans/grabs and a complete real-media download require operator configuration and remain unverified. No hard claim of <200 ms metadata search, <5 ms FTS at arbitrary library size, or guaranteed Cloudflare bypass is made. Public search can legitimately take up to the 2500 ms provider deadline, plus local overhead; the frontend should show a loading state and cache/debounce requests.

## Browser origin check

Next standalone builds `request.url` with its internal bind hostname, so `checkOrigin` compares the browser Origin with the incoming `Host` header (falling back to the request URL for direct calls). Mismatched and `null` origins are rejected; forwarded host headers are never trusted. Reverse proxies must preserve the original Host.
